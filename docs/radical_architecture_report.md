# 🏛️ Архитектурный аудит: Анатомия «костылей» и пути кардинальной перезагрузки

## 1. Честный диагноз: Почему проект ощущается «на костылях»?

Ваше ощущение абсолютно обоснованно и профессионально точно. Проект действительно пронизан архитектурными компромиссами и «костылями». 

Это произошло не из-за плохого кода, а из-за **фундаментального противоречия**:
> **Вы пытаетесь автоматизировать закрытые сторонние веб-сервисы (CSREP и FACEIT), у которых нет публичного машинного API для загрузки демок и которые агрессивно защищены антибот-системами (Cloudflare Turnstile, Cloudflare WAF, куки сессий).**

В результате архитектуре приходится постоянно притворяться живым человеком в браузере.

#### Костыль №1. Запуск полноценного браузера ради сетевых вызовов
Чтобы сделать `fetch()` к `csrep.gg`, Node.js запускает Chromium с графическим интерфейсом. Браузер ест 400–600 МБ оперативной памяти, блокирует папку сессии замками профиля (`SingletonLock`) и открывает окна на экране. Без этого Cloudflare возвращает 403 Forbidden.

#### Костыль №2. Кустарная криптография `X-Request-Secret`
Алгоритм в `src/domain/csrep-crypto.js`:
```javascript
for (let i = 0; i < str.length; i++) hash = (hash << 5) - hash + str.charCodeAt(i) | 0;
return (hash >>> 0).toString(36);
```
Это не открытый стандарт, а обфусцированный JS-код с фронтенда CSREP. Как только разработчики CSREP сменят соль, заголовок или добавят HMAC/Wasm — загрузка сломается у всех пользователей.

#### Костыль №3. Эмуляция действий пользователя в интерфейсе FACEIT
Вместо прямого API-запроса на получение ссылки, Playwright заходит на URL матча, ждет загрузки тяжелого SPA FACEIT, парсит селекторы кнопок (`button:has-text("Смотреть демо")`), кликает и слушает событие скачивания браузера. Если FACEIT изменит дизайн кнопки или язык интерфейса — клик перестанет работать.

#### Костыль №4. Ручная переавторизация и дампы сессий
Пользователь вынужден периодически вызывать мастер логина, чтобы обновить куки на диске. Куки хранятся в открытом виде, могут протухнуть посреди ночной очереди синхронизации.

#### Костыль №5. Файловая персистентность каменного века
История загрузок — это просто массив UUID в JSON-файле `uploaded_history.json`. Нет информации о времени загрузки, размере файла, количестве попыток, ошибках, нет возможности откатить отдельный матч или повторить сбойный.

## 2. Как улучшить проект кардинально? (3 архитектурных пути)

---

### 🌟 ПУТЬ 1 (ИДЕАЛЬНЫЙ): Браузерное расширение (Chrome / Edge Extension MV3)
*«Перенести логику туда, где уже есть всё необходимое»*

Вместо того чтобы симулировать браузер из Node.js, приложение переносится **внутрь реального браузера пользователя**.

#### Почему это уничтожает 95% всех костылей:
1. **Никакого Playwright и Chromium:** Потребление памяти 0 МБ (используется уже запущенный браузер).
2. **Никакого Cloudflare Turnstile:** Пользователь уже авторизован в своем Chrome на `csrep.gg` и `faceit.com`. Все запросы идут с легитимными куками, заголовками и TLS-отпечатком.
3. **Прямой UI-инъектинг:** Расширение встраивает красивую кнопку прямо в интерфейс CSREP:
   > `[⚡ Синхронизировать недостающие демки с FACEIT]`
4. **Автоматический сбор данных:** Расширение считывает недостающие демки прямо из Redux/DOM страницы CSREP и забирает ссылки с FACEIT через фоновый Service Worker.
5. **Фоновая загрузка:** Service Worker скачивает демку чанками в память через Web Streams API и параллельно пушит в Cloudflare R2 через multipart.
6. **Zero Setup для пользователя:** Не нужен Node.js, консоль, Git, npm, конфигурация портов. Установка в 1 клик из интернет-магазина Chrome.

```

│                 АРХИТЕКТУРА РАСШИРЕНИЯ                      │
├─────────────────────────────────────────────────────────────┤

│    └── Content Script инжектит кнопку и статус-бар          │

```

### ⚡ ПУТЬ 2: Легковесный Headless-демон без браузера (TLS Spoofing)
*«Если нужен автономный серверный скрипт / CLI для работы 24/7 без GUI»*

Если задача — гонять синхронизацию на VDS/сервере в фоне без рабочего стола:

1. **Выкинуть Playwright полностью.**
2. Использовать специализированный сетевой движок с эмуляцией отпечатков браузера:
   - В Node.js: библиотеки типа `curl-impersonate` / `tls-client`.
   - Либо переписать ядро на **Go** (`bogdanfinn/tls-client`) или **Python** (`curl_cffi`).
3. **Что это дает:**
   - Движок воспроизводит handshake реального Chrome (JA3/JA4 fingerprints, HTTP/2 SETTINGS frames, ALPN).
   - Cloudflare и FACEIT принимают запросы как запросы от реального десктопного Chrome.
   - Потребление RAM падает с **600 МБ до 15 МБ**.
   - Старт программы мгновенный (0.05 сек вместо 3–5 секунд запуска Playwright).

---

### 🛠️ ПУТЬ 3: Глубокий реинжиниринг текущей Node.js архитектуры
*«Если сохранять текущий стек (Node.js + Playwright + Web Studio), но сделать его взрослым»*

Если развивать текущий проект, вот что нужно переделать фундаментально:

#### 1. Переход с JSON на SQLite (`better-sqlite3`)
Вместо `uploaded_history.json` создается база данных:
```sql
CREATE TABLE matches (
  id TEXT PRIMARY KEY,           -- csrep match UUID
  faceit_id TEXT NOT NULL,       -- faceit match UUID
  map TEXT,                      -- de_mirage
  score TEXT,                    -- 13:11
  demo_size_bytes INTEGER,       -- 180482910
  status TEXT,                   -- PENDING | DOWNLOADING | UPLOADING | COMPLETED | FAILED | EXPIRED
  retry_count INTEGER DEFAULT 0,
  error_message TEXT,
  download_speed_mbps REAL,
  uploaded_at DATETIME,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```
**Эффект:** транзакционная надежность, аналитика, графики скорости, возможность нажать в UI кнопку «Перезапустить только упавшие демки».

#### 2. Архитектура очереди задач (Job Queue / State Machine)
Вместо жесткого процедурного цикла `for (match of matches)`:
- Создается пайплайн задач с конечным автоматом (FSM):
  `QUEUED → DOWNLOADING → UPLOADING → LINKING → DONE`
- Если отвалился интернет на 5-м чанке из 20, система не перезапускает всё заново, а возобновляет ровно с прерванного чанка.

#### 3. Разделение бэкенда и фронтенда
- Вынести `public/index.html` (1100 строк монолита с inline-скриптами) в современный Vite/React SPA с чистыми компонентами.
- Бэкенд превратить в строгий локальный REST/WebSocket демон с OpenAPI схемой.
